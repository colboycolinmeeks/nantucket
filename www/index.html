Why Nantucket?

I first used dBase at version II, on CP/M machines. Over my career I moved on to dBase III Plus, then Clipper, and later Harbour, or more specifically xHarbour. As technology advanced and more powerful systems and software came to the fore, xBase was all but forgotten.

I still often need to open DBF files. Over the years I've had to hunt for different ways of doing it, and none of them was as easy as dBase. With the arrival of AI-assisted development, I decided to write something in Go that gives a user interface very close to the original dBase.

The bigger picture goes further than DBF files: working with SQLite and other SQL databases using the xBase commands that many people still know well, and compiling programs into standalone executables.

Colin Meeks

What's in the box

The language you know

Clipper 5 and Harbour level: LOCAL, STATIC, PRIVATE and PUBLIC variables, code blocks, arrays, macros, BEGIN SEQUENCE, and xHarbour's FOR EACH, SWITCH, TRY/CATCH and hashes. The full Clipper preprocessor, with every dBase command defined in std.ch.

DBF and NTX

dBase III/IV and Clipper tables with DBT and FPT memos, and Clipper NTX indexes. USE, SEEK, REPLACE, SET RELATION, SORT, TOTAL, COPY TO, 250 work areas, and shared tables with real record and file locks.

Full screen, as it was

@…SAY…GET with PICTURE, VALID and READ; menus, Alert(), AChoice(); BROWSE, EDIT, and CREATE to design tables. Movable windows with the mouse, a status bar, and colour themes drawn in the classic VGA palette.

Reports and labels

REPORT FORM and LABEL FORM print dBase and Clipper .FRM and .LBL files, and full screen designers (CREATE REPORT, CREATE LABEL) make new ones.

An editor that compiles

MODIFY COMMAND opens a full screen editor with syntax highlighting, undo and WordStar blocks. Saving compiles your program, and an error keeps you on the faulty line.

Tests and packaging

nantucket test runs *_test.prg files with ASSERT and expected output. nantucket build packages a program as a single executable that runs without Nantucket installed.

Plus about 300 library functions for strings, numbers, dates, arrays, hashes and files. See every command.

A debugger worth opening

Press Alt+D while a program runs, call AltD(), or start with nantucket -debug. You see the source at the current line, the call stack, and every variable, LOCALs included.

  • Step into, over and out; run to the cursor
  • Breakpoints on lines and procedures, with conditions and hit counts
  • Logpoints that log a message without stopping
  • Watchpoints that stop when a variable changes
  • Data breakpoints that stop when a table field changes, in any record
  • Evaluate expressions and change values, LOCALs too

Get started

Nantucket is written in Go. Clone the repository and build it:

git clone https://github.com/colboycolinmeeks/nantucket
cd nantucket
make build              # or: go build -o nantucket ./cmd/nantucket

./nantucket             # the dot prompt
./nantucket myprog      # run myprog.prg
./nantucket examples/demo   # a guided tour

Building needs Go 1.26 or later. The documentation covers the language, the commands, the editor and the debugger.

Beta software

This is version 0.2, an early release. Much is still to be implemented, and some of what is there may not yet work correctly. Keep backups of any data you use it with. So far it has been built and tested on Linux (Fedora); Windows and macOS builds can be cross-compiled but haven't been tried yet. Bug reports and suggestions are very welcome on GitHub.

About the name

Clipper, the dBase compiler so many of us built our careers on, was created by the Nantucket Corporation, founded in 1984 by Barry ReBell and Brian Russell. Its releases were named after the seasons, such as Summer '87, and are still remembered fondly. Naming this project Nantucket is a nod to the people who created Clipper, and to everything it made possible for xBase developers.
